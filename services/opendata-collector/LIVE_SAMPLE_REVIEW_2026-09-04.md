## 범위와 실행 조건

공개 포털 목록을 최신순으로 조회해 FILE, API, LINKED는 각각 1,000개, 포털에 300개만 존재하는 STD는 300개를 MongoDB 격리 데이터베이스에 적재했다. FILE/API/LINKED는 `--page-size 1000 --max-pages 1 --max-details 1000`, STD는 그룹 내부의 12,708개 구성 데이터가 표본 상한을 넘지 않도록 `--max-member-pages 1`을 추가했다.

제한 실행이므로 FILE/API/LINKED의 `paused` 상태는 정상이다. STD는 다음 구성 페이지가 있는 그룹을 명시적으로 부분 상태로 기록하므로 `incomplete`가 정상이다. 제한 실행은 전체 스냅샷 완료 처리를 하지 않으므로 기존 문서를 비활성화하지 않는다.

## 적재 무결성

- 카탈로그 3,300건, 원천 레코드 3,300건이 모두 존재하고 빈 제목은 0건이다.
- 데이터셋 리소스 문서는 13,754건이다. 현재 활성 13,753건과 FILE 재수집 과정에서 보존된 비활성 이력 1건으로 구성된다.
- GridFS 원문/파싱 blob은 16,350건, 비압축 기준 약 915.1 MiB, gzip 저장 기준 약 115.1 MiB다.
- 리소스 원문 참조와 생성된 상세 파싱 참조가 가리키는 GridFS blob의 누락은 각각 0건이고, 저장된 상세 JSON 복원 실패도 0건이다. FILE 상세 HTTP 500 한 건은 상세 파싱 참조가 생성되지 않았으며 오류 상태와 목록 원문은 보존됐다.
- FILE의 파일 이력 999건, 과거 버전 상세 1,085건, 첨부 1,327건, 공개 OpenAPI 명세 645건, schema.org 문서 1,648건을 파싱했다.
- API의 schema.org 문서 2,000건, 내장/외부 OpenAPI 명세 797건, operation descriptor 262건과 operation 상세 262건을 보존했다.
- LINKED 상세 HTML과 schema.org는 각각 1,000건과 2,000건, DCAT은 응답 500인 네 건을 제외한 996건을 보존했다.
- STD의 schema.org 문서 600건, 첫 구성 페이지의 구성 데이터 750건과 구성 상세 750건을 보존했다. 별도로 파일 이력 상세 세 건과 operation 상세 37건을 보존했다.
- 완전 성공 항목의 기존 projection은 `open_file_info` 999건, `open_data_info` 1,000건이다. 부분 항목은 canonical `portal_catalog`와 GridFS에서 조회되며 기존 projection은 보수적으로 갱신하지 않는다.

## 실수집에서 발견하고 수정한 결함

1. 파일 이력이 없는 정상 응답이 스크립트만 반환할 때 오류 페이지로 오인했다. 포털의 정확한 빈 이력 스크립트 구조만 허용하고 점검 페이지 차단은 유지했다.
2. 상세 HTML과 외부 메타데이터의 문자열 안에 이스케이프하지 않은 따옴표와 CR 문자가 있어 JSON-LD 파싱이 실패했다. 완전한 문자열 속성 줄 내부만 보정한 뒤 `json.loads`로 다시 검증한다. 쉼표로 이어진 인용문처럼 구조와 구분하기 모호한 `description`은 보정 후보가 상세 화면의 별도 `설명` 값과 완전히 일치할 때만 승인한다.
3. DCAT 리터럴 값에 `<br>`, 태그처럼 보이는 일반 텍스트, 이스케이프하지 않은 `&`가 포함되어 XML 파싱이 실패했다. 허용한 RDF 리터럴 태그 중 XML 파싱에 실패한 본문만 텍스트로 보정하며, 정상 XMLLiteral 자식은 그대로 보존한다. 이후 다시 엄격 파싱하고 RDF 루트도 검증한다.
4. STD 목록 ID와 내부 PK가 다르고 JSON-LD까지 깨진 한 건에서 식별 검증이 중단됐다. 숫자 내부 PK, JSON-LD 오류, 실제 응답 URL과 요청 상세 URL의 일치, 목록·페이지 제목의 정확한 일치와 `표준데이터` 표기를 모두 만족할 때만 대체 검증을 허용했다.
5. API operation POST에 현재 포털 JavaScript가 요구하는 `publicDataPk`가 빠져 262개 operation이 전부 HTTP 500이었다. 파라미터를 추가한 뒤 실제 operation 262/262개를 수집했다. 국가중점 표준데이터의 `stdPublicDataPk` 분기도 반영했다.
6. 포털의 현재 외부 OpenAPI 경로인 `infuser.odcloud.kr/api/stages/{숫자}/api-docs`가 URL 허용 목록에 없었다. 숫자 stage ID의 정확한 경로만 허용했으며 표본 명세를 실제 재수집했다.

JSON-LD 85건과 DCAT 117건, 총 202개의 메타데이터 문법 오류를 재처리해 모두 복구했다. 파싱용 보정 사실은 상세 문서의 `metadata_repairs`에 기록하고, 포털이 반환한 원문은 GridFS에 그대로 보존한다. 구조 자체가 깨진 JSON/XML을 성공으로 오인하지 않는 음성 회귀 테스트도 포함했다.

모든 수정은 실패하는 회귀 테스트를 먼저 추가한 뒤 구현했다.

## 남은 원천 응답 오류와 표본 제한

| 유형 | 영향 카탈로그 수 | 상태 |
| --- | ---: | --- |
| FILE | 1 | 상세 엔드포인트가 재시도 후에도 HTTP 500을 반환해 상세 전체 실패 |
| LINKED | 4 | DCAT 엔드포인트가 재시도 후에도 HTTP 500을 반환해 부분 상태 |
| STD | 140 | `--max-member-pages 1` 표본 상한으로 다음 구성 페이지를 의도적으로 생략 |

HTTP 500 다섯 건은 응답 본문을 받지 못했으므로 수집기에서 내용을 복원할 수 없다. 오류와 목록 원문은 보존되어 있으며, 포털 응답이 정상화되면 같은 `collect` 갱신 경로에서 다시 수집된다.
