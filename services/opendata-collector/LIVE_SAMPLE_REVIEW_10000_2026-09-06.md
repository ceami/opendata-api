# data.go.kr 유형별 최대 10,000건 실수집 리뷰

검증 기간: 2026-09-04 ~ 2026-09-06 UTC

## 범위와 실행 조건

공개 포털 목록을 최신순으로 조회해 FILE과 API는 각각 10,000개 카탈로그를 수집했다. LINKED는 포털 목록의 교차 페이지 중복 때문에 11,000개 목록 행을 읽어 10,641개 고유 카탈로그를 발견했고, 그중 정확히 10,000개의 상세를 수집했다. 포털에 300개만 존재하는 STD는 300개 그룹을 모두 수집하되, 그룹 내부 구성 데이터 12,708건은 표본 크기를 통제하기 위해 `--max-member-pages 1`로 제한했다.

제한 실행이므로 FILE/API/LINKED의 `paused` 상태는 정상이다. LINKED에서 상세를 선택하지 않은 641건은 목록·원천 레코드까지만 보존했다. STD의 `incomplete`는 다음 구성 페이지가 있는 140개 그룹을 의도적으로 부분 상태로 기록한 결과다. 제한 실행은 전체 스냅샷 완료 처리를 하지 않으므로 기존 문서를 비활성화하지 않는다.

| 유형 | 포털 표시 총건수 | 상세 검토 표본 | 완전 성공 | 부분 | 상세 전체 실패 |
| --- | ---: | ---: | ---: | ---: | ---: |

## 적재 무결성

- 고유 카탈로그·원천 레코드는 각각 30,941건이고 빈 제목은 0건이다. LINKED의 상세 미선택 641건을 제외한 검토 표본은 30,300건이다.
- 검토 카탈로그에 연결된 리소스 문서는 152,213건이다. 활성 152,209건과 API 재수집 과정에서 보존된 비활성 이력 4건으로 구성된다.
- GridFS 원문·파싱 blob은 171,312건이다. 비압축 기준 7,507,121,024 bytes(약 7.0 GiB), gzip 저장 기준 1,046,816,663 bytes(약 998.3 MiB)다.
- 리소스 원문 참조와 상세 파싱 참조가 가리키는 GridFS blob 누락은 모두 0건이다. 상세 파싱 JSON 30,258건을 전부 압축 해제하고 다시 파싱했으며 복원 실패는 0건이다.
- FILE은 파일 이력 9,997건, 과거 버전 상세 38,938건, 첨부 17,309건, 공개 OpenAPI 명세 8,270건을 파싱했다.
- API는 공개 schema.org 문서 19,928건, 내장·외부 OpenAPI 명세 5,312건, operation descriptor와 operation 상세를 각각 3,449건 보존했다.
- LINKED는 상세 HTML·schema.org를 각각 9,997건 보존했고, DCAT은 9,896건을 보존했다.
- STD는 schema.org 문서 600건, 첫 구성 페이지의 구성 데이터 750건과 구성 상세 753건을 보존했다. 별도로 operation 상세 37건과 파일 이력 78건을 보존했다.
- 기존 조회용 projection은 `open_file_info` 9,997건, `open_data_info` 9,964건이다. 부분·전체 실패 항목은 canonical `portal_catalog`와 GridFS에서 조회하며 projection은 보수적으로 갱신하지 않는다.
- 파싱용 보정은 JSON-LD 824개 카탈로그에서 따옴표 3,235곳, DCAT 688개 카탈로그에서 수행했다. 보정 사실은 `metadata_repairs`에 기록했고 포털 원문은 변경하지 않고 GridFS에 보존했다.

## 10,000건 실행에서 발견하고 수정한 결함

1. LINKED 목록 11,000개 행에서 359개의 교차 페이지 반복 행이 발생했다. 기존 코드는 첫 반복을 발견하면 이후 페이지를 중단해 1,960개 고유 항목만 남겼다. 이제 중복 플래그를 유지해 실행을 완료로 판정하지 않으면서도 이후 페이지의 새 항목은 계속 보존한다. 회귀 테스트는 반복 뒤 페이지의 새 ID가 수집되고 실행 상태는 `incomplete`로 유지되는지 확인한다.
2. API 51건의 ``swaggerJson = `undefined` `` 선언을 손상 명세로 오인했다. 정확한 문자열 리터럴 `undefined`만 명세 없음으로 처리해 모두 복구했다.
3. API 2건은 Swagger JSON 설명 안의 문서용 백틱을 템플릿 종료자로 오인했다. 세미콜론으로 끝나는 할당문의 경계만 선택하고 최종 JSON 구조를 다시 검증해 두 건 모두 복구했다. 손상 JSON 거부는 유지했다.
4. FILE 8건은 `dct:conformsTo` 리터럴 안에 포털이 XML로 이스케이프하지 않은 텍스트·`br` 태그를 포함했다. 해당 RDF 리터럴 필드만 기존의 엄격한 보정 대상에 추가했고 구조가 손상된 XML을 성공 처리하지 않는 음성 테스트를 함께 통과했다.
5. FILE 1건은 포털이 공개 OpenAPI 명세를 `http://infuser.odcloud.kr/oas/...`로 게시했다. 동일 HTTPS URL이 JSON 200을 반환함을 확인한 뒤 정확한 `infuser.odcloud.kr/oas/` 경로만 HTTPS로 승격했다. 다른 HTTP·외부 목적지 차단은 유지했다.

위 코드 관련 실패 62건은 최종 재수집에서 모두 복구됐다. API의 일시적 HTTP 500 한 건도 두 번째 시도에서 복구됐다.

실행 도중 MongoDB 컨테이너가 호스트 root 프로세스의 SIGTERM으로 한 차례 정상 종료됐다. `OOMKilled=false`, MongoDB 종료코드 0이고 WiredTiger 종료 체크포인트가 완료됐다. 중단된 `processing` 10건과 LINKED 상세 예산 3건을 복구한 뒤 이어서 실행했으며, 최종 건수와 참조 무결성에 불일치는 없었다.

## 남은 원천 응답 오류와 표본 제한

최초 처리 후 실패 항목만 별도 배치로 한 번 더 요청했다. 아래 HTTP 500은 두 번째 시도 후에도 남은 포털 원천 응답 오류다.

| 유형 | 영향 카탈로그 수 | 최종 상태 |
| --- | ---: | --- |
| FILE | 3 | 상세 엔드포인트 HTTP 500, 상세 전체 실패 |
| API | 36 | 상세 엔드포인트 HTTP 500, 상세 전체 실패 |
| LINKED | 99 | DCAT 엔드포인트 HTTP 500, 상세 HTML·schema.org는 보존된 부분 상태 |
| LINKED | 5 | 재시도 시 상세 엔드포인트 HTTP 500, 전체 실패 상태; 이전에 받은 원문이 있으면 이력은 유지 |
| STD | 140 | `--max-member-pages 1` 표본 상한으로 다음 구성 페이지를 의도적으로 생략 |

지속 HTTP 500은 합계 143개 카탈로그다. 응답 본문을 받지 못한 데이터는 수집기에서 복원할 수 없으며, 오류와 확보한 목록·원문은 보존했다. 포털 응답이 정상화되면 같은 `collect` 갱신 경로에서 다시 수집할 수 있다.

## 자동 검증

최종 코드로 MongoDB 미지정 수집기 테스트 111개 통과·조건부 4개 건너뜀, 실제 MongoDB 수집기 테스트 115개 통과, 카탈로그 조회 API 테스트는 인메모리와 실제 MongoDB에서 각각 27개 통과했다. 수집기 Ruff lint·format 검사, CLI 진입점과 `git diff --check`도 통과했다.

이 실수집은 공개 카탈로그와 명세 메타데이터 검증이다. 개별 업무 API의 데이터 행, 전체 다운로드 파일 바이트, 외부 연계 사이트의 재귀 수집은 포함하지 않는다.
